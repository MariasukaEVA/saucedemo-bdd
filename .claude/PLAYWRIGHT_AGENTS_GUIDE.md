# Playwright 1.56 Agents Integration Guide

## Overview

Playwright 1.56 introduces **Playwright Agents** — three agentic LLM definitions designed to automate core testing workflows. These agents integrate seamlessly with Claude Code to:

1. **🎭 Planner** — Explore your app and produce Markdown test plans
2. **🎭 Generator** — Transform Markdown plans into Playwright Test files
3. **🎭 Healer** — Execute tests and automatically repair failing tests

## Setup Steps

### Step 1: Ensure Playwright 1.56 is Installed

Your `package.json` has been updated to:
```json
{
  "@playwright/test": "^1.56.0",
  "playwright": "^1.56.0"
}
```

**To complete installation** (if you encountered permission issues):
```bash
# Option A: Close all VS Code instances and retry
npm install

# Option B: Use npm ci (cleaner approach)
npm ci

# Option C: Manual clean install
rm -r node_modules package-lock.json
npm install
```

### Step 2: Initialize Agent Definitions

Once Playwright 1.56 is installed, initialize the agent definitions:

```bash
npx playwright init-agents --loop=claude
```

This creates agent configuration files in your project root.

## How Agents Work in Your BDD Project

### Agent 1: Planner 🎭
**Purpose**: Analyze your SauceDemo app and generate a test specification

**Usage in Claude Code**:
```
Use the Planner agent to explore the login flow and create a test plan for:
- Valid login with standard_user
- Invalid login with bad credentials  
- Locked-out user error handling
```

**Output**: A Markdown document describing test steps, expected outcomes, and edge cases

### Agent 2: Generator 🎭
**Purpose**: Transform Planner output into actual Playwright code

**Expected Output**: 
- `.spec.ts` files with Playwright test code
- Page objects (if applicable)
- Test configuration

**Integration with Your BDD Stack**:
Since your project uses **Cucumber + TypeScript** (not pure Playwright), you would:
1. Use Generator to create `.spec.ts` files as reference
2. Manually adapt the generated code into your `.steps.ts` files
3. Update your page objects in `src/pages/` with any new selectors

### Agent 3: Healer 🎭
**Purpose**: Run tests and auto-repair failures

**Usage**:
- Run your Cucumber tests
- Identify failures
- Let Healer suggest fixes (e.g., updated selectors, timing issues)

**In Your Workflow**:
```bash
npm run test:smoke  # Run tests
# Tests fail → share failure output with Healer agent
# Healer analyzes screenshots, console logs, and suggests fixes
```

## Practical Workflow: Adding a New Checkout Feature

### Example: Add "Apply Promo Code" test

**Step 1: Use Planner**
```
Prompt Planner Agent:
"Explore https://www.saucedemo.com and plan tests for a promo code feature.
Include: valid codes, expired codes, single-use codes."
```

**Output** (Markdown Plan):
```markdown
# Promo Code Feature Tests

## Test Cases:
1. Apply valid promo code → 10% discount applied
2. Apply invalid code → "Invalid promo code" error
3. Apply expired code → "Promo code expired" error

## Page Elements:
- Promo input: [data-test="promo-code-input"]
- Apply button: [data-test="apply-promo"]
- Discount label: [data-test="discount-amount"]
```

**Step 2: Use Generator**
```
Prompt Generator Agent:
"Using this test plan, generate Playwright tests for the promo code feature."
[paste the plan]
```

**Output**:
```typescript
// Generated by Playwright Generator
test('Apply valid promo code', async ({ page }) => {
  await page.goto('https://www.saucedemo.com/checkout');
  await page.locator('[data-test="promo-code-input"]').fill('SUMMER10');
  await page.locator('[data-test="apply-promo"]').click();
  expect(page.locator('[data-test="discount-amount"]')).toContainText('10%');
});
```

**Step 3: Adapt to Your BDD Format**

Convert the generated test into your Cucumber steps:

```typescript
// src/steps/checkout/checkout.steps.ts

When('I enter promo code {string}', async function (this: PlaywrightWorld, code: string) {
  const checkoutPage = new CheckoutPage(this.page);
  await checkoutPage.enterPromoCode(code);
});

Then('the discount should be {int}%', async function (this: PlaywrightWorld, discountPercent: number) {
  const checkoutPage = new CheckoutPage(this.page);
  const discountText = await checkoutPage.getDiscountAmount();
  expect(discountText).toContain(`${discountPercent}%`);
});
```

Add to your page object:
```typescript
// src/pages/checkout.page.ts

async enterPromoCode(code: string): Promise<void> {
  await this.fill('[data-test="promo-code-input"]', code);
  await this.click('[data-test="apply-promo"]');
}

async getDiscountAmount(): Promise<string> {
  return this.getText('[data-test="discount-amount"]');
}
```

## Key Advantages for Your Project

| Aspect | Benefit |
|--------|---------|
| **Selector Discovery** | Planner finds all data-test attributes automatically |
| **Test Generation** | Generator scaffolds tests quickly; you adapt to Cucumber |
| **Failure Diagnosis** | Healer analyzes screenshot + console logs + network requests |
| **Page Objects** | Generator suggests object structure; you refine with your BasePage pattern |
| **Cross-Environment** | All three agents work with your ENV variable setup |

## Best Practices for BDD + Agents

### DO ✅
- Use Planner to explore features before writing scenarios
- Use Generator to spike complex page interactions
- Use Healer to analyze failure root causes (network, timing, selectors)
- Keep agent outputs in your Git history for auditing
- Combine agent-generated code with your BDD naming conventions

### DON'T ❌
- Copy-paste generated code directly without review
- Bypass your page object pattern
- Use agent code without testing it first
- Replace manual test design with pure generation (balance is key)

## Integration with Your CI/CD

Your GitHub Actions workflow (4-shard matrix) can include agent-assisted repair:

```yaml
- name: Run tests
  run: npm run test:regression

- name: Analyze failures with Healer
  if: failure()
  run: |
    # Export failure artifacts
    tar -czf failures.tar.gz reports/ allure-results/
    # Let Healer analyze (manual invocation in Claude Code)
    echo "Review failures.tar.gz with Healer agent"
```

## Troubleshooting

### Issue: "Agent definition not found"
**Solution**: Ensure `npx playwright init-agents --loop=claude` completed successfully. Check for `.agentloop/` directory.

### Issue: "Generator creates @playwright/test syntax"
**Solution**: This is expected. Extract the test logic and adapting to Cucumber/TypeScript:
- The locator selectors are still valid
- The interaction patterns (click, fill, check) map 1:1 to your BasePage methods
- Convert `expect()` calls to match your assertion style

### Issue: "Healer suggests outdated selectors"
**Solution**: 
1. Run Planner again to re-explore current selectors
2. Share current page structure with Healer in your prompt
3. Test suggested fixes locally before applying
